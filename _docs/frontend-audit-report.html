Frontend Audit Handoff

Date: 2026-10-31 · Scope: React/Vite client, auth and recipe flows, grocery sidebar, URL import, lint/build, Playwright desktop and mobile Chromium, Node runtime migration.

Disposition: All actionable findings discovered in this pass were fixed. Three non-blocking lint warnings and one incomplete full Docker image build remain. Firefox and WebKit were run in the later verification pass.

Findings

ID Severity Finding Status
FE-01 High Selected recipe IDs started empty, then a mount effect could overwrite the persisted local-storage selection before hydration completed in Strict Mode. Fixed: synchronously hydrate and validate the state initializer in MainLayout.tsx.
FE-02 High Every selected recipe was merged into the already-persisted grocery list on reload. Playwright reproduced a quantity of 3 becoming 6; the effect also captured stale list state. Fixed: process newly selected IDs only after hydration and merge using functional state updates. Regression test added.
FE-03 Medium Grocery edit/delete/done actions were clickable spans without keyboard semantics, labels, or focus indication. Fixed: labeled buttons, focus styling, and keyboard regression test.
FE-04 High Console diagnostics exposed OAuth state/session storage, refresh response tokens, Axios headers, and private recipe/OCR content. Fixed: remove payload logs or retain only sanitized labels/statuses across auth and user-content flows.
FE-05 Medium Protected-route return state was lost when Google OAuth left the SPA for a full-page redirect. Fixed: validated same-origin session-storage destination and stable post-login target; browser coverage added.
FE-06 Medium Lint errors included JSX in a .js asset, explicit any in OCR/API request code, and redundant catch handling. Fixed: removed the unreferenced malformed file, typed request data, and removed unsafe casts.
FE-07 Feature Grocery items had no direct Google Keep export. Implemented: copy unchecked items as normalized one-per-line text with toast feedback; Playwright covered.
FE-08 Feature The client had no protected shared-recipe preview and accept journey. Implemented: share action, preview route, return handling, and accept flow; Playwright covered with API stubs.
FE-09 Feature/Security OCR import had no URL source or server-side public HTML/JSON-LD parser. Implemented: URL tab, reusable editable preview, authenticated/rate-limited endpoint, schema.org Recipe parser, DNS pinning, private-IP rejection, redirect revalidation, 8-second deadline, 3 MiB cap, and focused tests.
FE-10 High PKCE used the frontend callback while the server exchange could use the legacy API GOOGLE_CALLBACK_URL, causing a redirect URI mismatch. Fixed by separating GOOGLE_PKCE_REDIRECT_URI and VITE_GOOGLE_PKCE_REDIRECT_URI, and rejecting exchange URI mismatches. The exact frontend callback still must be registered in Google Cloud Console.
FE-11 High Mobile shell was broken: the drawer was 100% wide so the backdrop could never be tapped, the close tab was pinned over the header, drawers used conflicting CSS in two files, the two-row header overflowed its fixed height, the .nav-search* classes had no CSS, closed drawers stayed focusable, and there was no Escape or in-panel Close. Rebuilt: 88vw drawers with a tappable scrim, in-panel Close, Escape, swipe-to-close, close on route change, one drawer at a time, scroll lock, focus trap, inert when closed, a bottom dock (Grocery, Copy to Google Keep, Recipe index), single-row header with collapsible search, FAB and toasts moved clear of the dock. Desktop edge tabs unchanged.
FE-12 High The chef graphic rendered at a fixed 500px and overflowed phone viewports; Chrome then enlarged the layout viewport (545px vs 393px), stretching every fixed element. Old overflow tests passed anyway because they compared against the inflated innerWidth. Capped the SVG; overflow tests now compare against the emulated viewport width.
FE-13 Feature The Keep export button lived only inside the closed drawer. "Copy to Google Keep" is now in the mobile dock and desktop header via a shared event; the drawer also offers Share (native share sheet where supported) and an Open Keep link.
FE-14 Feature Import confirmation showed only the parsed result, so users could not verify it against the source. New ImportReview: swipeable Original vs Parsed on phones/tablets (scroll-snap, tabs, arrow keys), side by side at 1100px+. Original shows zoomable uploaded images, recognized text, pasted text, or the source URL and its images.
FE-15 Medium OCRModal lost selected files on tab switch, did not reset after import/close, had no Escape, focus trap or scroll lock, and was unusable on phones. Files retained with thumbnails and validation; state resets on close; Escape, focus trap and scroll lock; full-screen sheet with sticky actions on phones; 16px inputs.
FE-16 High/Security OCR routes had no per-route auth or ownership checks; DELETE joined a client id into a path with no traversal guard; the image guard used startsWith(dir); uploads used the client filename with no type/count limits; /ocr/parse logged a token fragment and the request body. (The /api stack already required a JWT, so these were not anonymous in practice, but nothing scoped files to owners.) Router-level auth, owner-prefixed sanitized filenames resolved only for their owner, path containment, multer limits, job ownership check, logging removed, authenticated gallery images. Regression suite added.
FE-17 Test Flaky OAuth-callback e2e (2 of 5 runs failed). Test-isolation bug, not a product bug: the silent /auth/refresh after reload hit the real network. The test now stubs /auth/.
